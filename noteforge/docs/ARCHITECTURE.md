# Архитектура NoteForge

## Принцип

Единственный источник истины — **музыкальная модель** (`src/model`). Всё остальное
вычисляется из неё:

```
            ┌──────────────── правки (Immer, undo/redo) ───────────────┐
            ▼                                                          │
   Score (модель) ──► MEI (src/engrave/mei.ts) ──► Verovio (Web Worker) ──► SVG-страницы
        │                                                              │
        ├──► .nfg (JSON) — сохранение/открытие                          └─► клики → id элемента → модель
        ├──► MIDI / воспроизведение            (этап 2)
        ├──► MusicXML импорт/экспорт           (этап 4)
        └──► PDF / печать                      (этап 4)
```

Verovio используется только как гравёр: все музыкальные решения (какие знаки
альтерации печатать, как группировать ребра, какая нота с какой залигована)
принимает NoteForge и явно кодирует их в MEI. Поэтому то, что видно на листе,
совпадает с тем, что хранится в модели и (на этапе 2) звучит.

## Модель

* Время — точные дроби, без плавающей точки: `3/16` — это пунктирная восьмая.
* Такт фортепиано: два нотоносца (`staves[0]` — правая рука, `staves[1]` — левая),
  у каждого до 4 независимых голосов.
* **Инвариант:** каждый непустой голос ровно заполняет свой такт (паузы — явные
  события). Голос 1 никогда не пуст. Это проверяется тестами и при открытии файла.
* Размеры и тональности хранятся как *изменения* в `Score.measures[i]`
  (на первом такте — всегда).
* Лига (`note.tie`) — признак ноты; она отображается, только если в следующем
  событии того же голоса есть нота той же высоты.

### Ввод с перезаписью

Как в MuseScore: запись события длиной `L` в позицию `t` заменяет всё, что было в
`[t, t+L)` этого голоса; обрезанные ноты укорачиваются, остаток заполняется
выровненными по долям паузами. Если событие не помещается до тактовой черты, оно
продолжается в следующем такте залигованными нотами (при необходимости
добавляется новый такт).

### Смена размера

`setTimeSig` перегруппировывает музыку от выбранного такта до следующей смены
размера: ноты раскладываются по новым тактам, пересекающие черту — делятся и
лигуются, тональности переносятся в такт, где они начинались.

## Передача мелодии между руками (этап 3, заложено в модели)

Каждое событие однозначно принадлежит (нотоносец, голос). На этапе 3 добавляются:

* `MelodyLine` — именованная линия, объединяющая события из любых нотоносцев/голосов
  (ссылки на id событий) в одну фразу; используется для подсветки и для отдельного
  прослушивания мелодии/сопровождения;
* межнотоносцевые события (`staffOverride` у аккорда → MEI `@staff` у ноты/аккорда,
  межстановые ребра через `<beam>` со смешанными `@staff`), которые Verovio
  гравирует нативно.

Сейчас мелодию уже можно записать «по рукам» (C5 → B4 в правой, A4 → G4 в левой);
связывание в одну линию — следующий этап.

## Производительность

* Раскладка Verovio выполняется в Web Worker — интерфейс не блокируется.
* Частые правки объединяются: пока идёт раскладка, хранится только последний запрос.
* Отображаются только страницы рядом с видимой областью (IntersectionObserver),
  дальние SVG выгружаются из памяти.
* Отмена/повтор — снимки неизменяемой модели (Immer), правка одного такта не
  копирует остальные.

Измерено (Node, 1500 тактов фортепиано, ~18 000 нот, 63 страницы): правка модели
≈ 2 мс, генерация MEI ≈ 90 мс, полная раскладка Verovio ≈ 2,9 с. Для очень длинных
произведений на этапе 5 планируется разбиение раскладки по частям/разделам и
повторная раскладка только изменённого участка.

## Хранение

`.nfg` — JSON:

```json
{ "format": "noteforge", "formatVersion": 1, "app": "0.1.0", "savedAt": "…", "score": { … } }
```

Запись атомарная: временный файл → проверка → предыдущая версия копируется в
`<имя>.nfg.bak` → переименование. При открытии файл проходит проверку структуры;
восстановимые ошибки (неполные/переполненные такты, дубли id) исправляются с
отчётом пользователю, невосстановимые — файл не открывается.
