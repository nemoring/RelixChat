# Архитектура NoteForge

## Принцип

Единственный источник истины — **музыкальная модель** (`src/model`). Всё остальное
вычисляется из неё:

```
            ┌──────────────── правки (Immer, undo/redo) ───────────────┐
            ▼                                                          │
   Score (модель) ──► MEI (src/engrave/mei.ts) ──► Verovio (Web Worker) ──► SVG-страницы
        │                                                              │
        ├──► .nfg (JSON) — сохранение, автосохранение                   └─► клики → id элемента → модель
        ├──► Performance (src/playback/perform.ts) ──► SF2-синтезатор / Web MIDI / MIDI-файл / WAV
        ├──► MusicXML экспорт ◄──► импорт (src/io)
        └──► MEI полной раскладки (отдельный воркер) ──► SVG ──► PDF / печать (скрытое окно Chromium)
```

Verovio используется только как гравёр: все музыкальные решения (какие знаки
альтерации печатать, как группировать ребра, какая нота с какой залигована)
принимает NoteForge и явно кодирует их в MEI. Поэтому то, что видно на листе,
совпадает с тем, что хранится в модели и (на этапе 2) звучит.

## Модель

* Время — точные дроби, без плавающей точки: `3/16` — это пунктирная восьмая.
* Такт фортепиано: два нотоносца (`staves[0]` — правая рука, `staves[1]` — левая),
  у каждого до 4 независимых голосов.
* **Инвариант:** каждый непустой голос ровно заполняет свой такт (паузы — явные
  события). Голос 1 никогда не пуст. Это проверяется тестами и при открытии файла.
* Размеры и тональности хранятся как *изменения* в `Score.measures[i]`
  (на первом такте — всегда).
* Лига (`note.tie`) — признак ноты; она отображается, только если в следующем
  событии того же голоса есть нота той же высоты.

### Ввод с перезаписью

Как в MuseScore: запись события длиной `L` в позицию `t` заменяет всё, что было в
`[t, t+L)` этого голоса; обрезанные ноты укорачиваются, остаток заполняется
выровненными по долям паузами. Если событие не помещается до тактовой черты, оно
продолжается в следующем такте залигованными нотами (при необходимости
добавляется новый такт).

### Смена размера

`setTimeSig` перегруппировывает музыку от выбранного такта до следующей смены
размера: ноты раскладываются по новым тактам, пересекающие черту — делятся и
лигуются, тональности переносятся в такт, где они начинались.

## Передача мелодии между руками

* Каждое событие однозначно принадлежит (нотоносец, голос) — это определяет руку, ритм и звучание.
* `ChordEvent.staffShift` — межстановая запись: событие рисуется на соседнем стане (MEI `@staff`),
  Verovio строит межстановые рёбра и лиги; на звучание и микшер это не влияет.
* `ChordEvent.line` + `Score.lines` — мелодическая линия: набор событий из любых станов и голосов.
  Используется для подсветки и соединительной линии на листе, для ввода (новые ноты попадают в активную линию)
  и для микшера: каналы «Мелодия» и «Сопровождение» с отдельной громкостью, выключением и соло.
* В MusicXML линия сохраняется как цвет нот и восстанавливается при импорте.

## Исполнение

`perform()` строит из модели список нот с секундами и тиками (PPQ 480):

* **Порядок тактов** (`unroll`): повторы с вольтами, затем D.C./D.S.; после перехода повторы не берутся,
  играется последняя вольта; Fine завершает, To Coda переходит к Коде.
* **Время**: темп каждого такта; ферматы растягивают свой участок вдвое (обратное отображение для курсора).
* **Громкость**: уровни динамики по партии, вилки — линейное нарастание к следующему уровню; акценты, sf/fp.
* **Длительность**: стаккато 50 %, стаккатиссимо 30 %, обычные ноты 97 %; лиги склеивают ноты в одну;
  педаль продлевает ноты до снятия.
* **Форшлаги и орнаменты**: форшлаги берут время у главной ноты; трель, морденты и группетто
  раскладываются на ноты по ступеням тональности.

Синтезатор один и тот же для живого звука (AudioContext) и для WAV (OfflineAudioContext). WAV рендерится
кусками по 8 с с перекрытием «хвостов», поэтому даже часовые произведения не требуют много памяти.

## Производительность

* Раскладка Verovio выполняется в Web Worker — интерфейс не блокируется.
* Частые правки объединяются: пока идёт раскладка, хранится только последний запрос.
* Отображаются только страницы рядом с видимой областью (IntersectionObserver),
  дальние SVG выгружаются из памяти.
* Отмена/повтор — снимки неизменяемой модели (Immer), правка одного такта не
  копирует остальные.

* **Быстрый путь** (`fastLayout.ts`). Если правка затронула только ноты, страница с изменёнными тактами
  размечается отдельно во втором воркере. Используются её прежние разрывы систем, прочитанные из SVG.
  Полная раскладка выполняется с задержкой 350 мс после последней правки и затем заменяет страницы.
* **Измерено** (Electron, 1500 тактов, ~18 000 нот, 63 страницы):
  * открытие файла и первая страница — ~3 с;
  * правка видна через ~0.3–0.5 с;
  * полная раскладка — ~2–2.5 с.

## Хранение

`.nfg` — JSON (формат версии 1; старые файлы этапа 1 открываются, новые поля заполняются по умолчанию):

```json
{ "format": "noteforge", "formatVersion": 1, "app": "0.1.0", "savedAt": "…", "score": { … } }
```

Запись атомарная: временный файл → проверка → предыдущая версия копируется в
`<имя>.nfg.bak` → переименование. При открытии файл проходит проверку структуры;
восстановимые ошибки (неполные/переполненные такты, дубли id) исправляются с
отчётом пользователю, невосстановимые — файл не открывается.

## Автосохранение и восстановление

* **Метка сессии.** При запуске главный процесс создаёт `userData/session.lock`.
* **Автокопии.** Документ с несохранёнными изменениями периодически пишется в `userData/autosave/<ключ>.nfg`.
* **Чистый выход** удаляет автокопии и метку.
* **После сбоя.** Если при запуске метка уже существует, значит прошлый запуск завершился аварийно,
  и интерфейс предлагает восстановить найденные копии.
