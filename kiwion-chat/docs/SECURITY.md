# Безопасность Kiwion Chat

| Требование | Реализация |
|---|---|
| HTTPS | Caddy с Let's Encrypt (`deploy/Caddyfile`), HSTS при `KIWION_HTTPS=1`; Android запрещает cleartext (`usesCleartextTraffic=false`) |
| Безопасная авторизация | Argon2id для паролей; сессионные токены 256 бит, в БД только HMAC-хеш; срок жизни, отзыв сессий и устройств; блокировка перебора (8 ошибок / 15 мин на email) |
| Ограничение частоты | скользящее окно по IP / пользователю / ключу: вход, регистрация, письма, отправка сообщений, API (RPM на ключ) |
| SQL-инъекции | только ORM SQLAlchemy и параметризованные запросы; тест с инъекционными строками |
| Проверка входных данных | Pydantic-схемы с длинами, шаблонами и диапазонами; лимит тела запроса 1 МБ; лимит длины сообщения |
| Секреты | только через переменные окружения / `.env` (в `.gitignore`); в production сервер не стартует без сильных секретов |
| Защита API-ключей | `kw-…` 256 бит, хранится HMAC-хеш и префикс, показ один раз, отзыв, лимиты |
| Изоляция данных | каждый запрос к чатам/ключам/сессиям фильтруется по владельцу; чужие объекты → 404 (тесты) |
| Логи без утечек | `RedactingFilter` вырезает Bearer-токены, `kw-`/`kws_`, пароли и секреты из логов и журнала ошибок |
| Backend ↔ inference | HMAC-SHA256 подпись (метка времени ±60 с, nonce против повтора) + WireGuard и/или mTLS со своим CA; llama-server слушает только 127.0.0.1 |
| Веб-клиент | строгий CSP (`script-src 'self'`, без inline-скриптов и eval), DOMPurify для Markdown, `X-Frame-Options: DENY`, `nosniff` |
| Злоупотребления | proof-of-work при регистрации, лимит регистраций с IP и аккаунтов на устройство, запрет временной почты и email-псевдонимов, антифрод рефералов, блокировка пользователей с отзывом сессий и ключей |
| Админка | все `/api/admin/*` требуют `role=admin` на сервере; журнал действий администраторов; админ не может заблокировать сам себя |

## Ограничения, о которых стоит знать

- Rate-limit хранится в памяти процесса: запускайте один процесс backend (так и настроено) или
  перенесите лимиты в Redis при масштабировании.
- Веб-клиент хранит токен в `localStorage`; от XSS защищают строгий CSP и санитизация Markdown.
- `device_id` формирует клиент; это сигнал для антифрода, а не доказательство.
